# T7-07 · Audit coverage and RBAC matrix — builder brief

Written by the Opus test writer (t7-tests) on 2026-11-20. Branch `feat/t7-07-rbac-audit` from `origin/main`.
**Start after T7-04 is merged** (its staff guard gives clients 403 on staff routes before body validation) and rebase
onto main again before review. The acceptance tests are on the branch; make them pass without editing them.

## Goal
1. Every Aprende route answers each caller as the matrix says: anonymous, client (own resource / another client's),
   paralegal, attorney, admin. The matrix is `tests/rbac_matrix.yaml`; the test generates the calls from `app.routes`,
   so a new route without an entry fails.
2. Every state-changing Aprende route (POST, PUT, PATCH, DELETE) writes an audit row when it succeeds, and a refused
   request writes none.

This extends T7-04's generated RBAC test (staff routes, client → 403) to every route and role; it does not replace it.

## The access rule (what the test checks)
- **Anonymous → 401** on every route except `public` ones (`POST /payments/webhook`, and T7-05's `GET /settings/public`).
- A role the matrix does not allow → **403**, whatever the query or body (`{}` here). A role it allows → anything but
  401/403, and never 5xx (404, 409, 422 are fine with the test's placeholder ids and empty bodies).
- `other: true`: another client's booking, document or signed document → 403 or 404, and none of its content.
- So the identity and role check must run **before** FastAPI validates the query and the body.

## How: one auth module, used as dependencies
New `backend/aprende/auth.py`:
```python
def client_user(authorization: str = Header(None)) -> dict          # 401 no/unknown token, 403 not a client or no adult flag
def client_journey(user: dict = Depends(client_user)) -> dict        # journey.get_or_create_for_user(user["id"])
def signed_in(authorization: str = Header(None)) -> dict             # 401 only
def staff(*roles: str)                                               # -> a dependency: 401, 403 unless the role is in roles
                                                                     #    (no roles = paralegal, attorney, admin)
```
FastAPI resolves dependencies before it validates query and body, so a route declared as
`def post_attempt(body: Attempt, j: dict = Depends(auth.client_journey))` answers 401/403 first.
Replace the local copies (`_staff`, `_client`, `_auth`, `_journey`, `_adult_check`, `chat._client_journey`'s identity
part …) in `backend/aprende/*.py` with these; gate checks (409 `{"error": "gate", ...}`) stay in the handlers.
Role sets do not change except: `GET /signed-documents/{did}` is client-only (staff 403, not 404).
Keep T7-04's middleware (it covers `/staff/…` and `/conflicts` early); the two agree.

## Audit
For a 2xx answer to POST/PUT/PATCH/DELETE on an Aprende path, one middleware in `app.py` writes
`log_audit(actor, f"{method} {route.path}", "route", <path params joined by ",">, "")` **unless the handler already
wrote a row for this request** (compare `len(backend_app.audit)` before and after). `actor` = the caller's email;
`"stripe"` for the webhook. Write it holding `_request_lock` (the legacy store; as `legacy.py` does). The detail never
holds client text, names or answers. Refused requests (401/403/422/409) write nothing.
Handlers that already log (T7-01 content, T3-06 characters, review) keep their own rows.
