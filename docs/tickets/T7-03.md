# T7-03 · Characters admin — builder brief

Written by the Opus test writer (t7-tests) on 2026-11-19. Branch `feat/t7-03-characters-admin`, based on
`feat/t7-01-content-admin` (it reuses T7-01's content functions). The acceptance tests are on the branch; make them pass
without editing them.

## Goal
Staff turn characters on or off, assign them to units, and hear a voice preview, without a developer. On/off and units
take effect on the client's next lesson load. The voice preview is the browser's own speech synthesis (decision F-003:
no server voice). Persona prompts become T7-01 content entries (`kind = persona`) and follow the same attorney-approval
rules (spec 11 "Personajes"; T5-07: attorney approval required before clients see them).

`learn.get_map` and `learn.get_lesson` use these on every call (no cache): a lesson's `character` is
`lesson_character(lesson.unit, lesson.character)`; an item's `character` is `item_character(item.character, host)`.
A disabled character never appears in a map, a lesson or an item. `POST /chat` with a disabled character → 422
(as for an unknown one). Seed assignments stay (migration 0002).

## 2. Routes
| Method + path | Roles | 200 | Errors |
|---|---|---|---|
| `GET /staff/characters` (new) | staff | `[{"id", "name_key", "enabled", "units", "voice_es", "voice_en"}]` — every character, disabled ones too | 401/403 |
| `PATCH /characters/{id}` (exists, T3-06) | staff | as today | 422 a unit not in `UNITS`; 409 disabling calavera (as today) |

Unit rule: a unit has one host. Assigning unit U to character X removes U from every other character in the same
transaction. The PATCH stays audited (`character_update`, as today).

## 3. Persona prompts as content (`kind = persona`), extending T7-01's `content.py` / `routes_content.py`
Entries come from `aprende/content/personas.yaml` (the seed, live version 0), all **legal** (attorney approval):
| `entry_id` | body |
|---|---|
| `persona:shared` | `{"text": str}` |
| `persona:modes.learn`, `persona:modes.intake` | `{"text": str}` |
| `persona:characters.<id>` (calavera, oso, pinata) | `{"name": {"es": str, "en": str}, "persona": str}` |

- `GET /staff/content?kind=persona` lists the 6 entries; detail/draft/submit/approve/preview work as for the others.
- The model instructions are English only (T5-07), so the two-language rule applies to `name` only:
  `missing_languages(body["name"])` → 422 `{"error": "languages", "missing": [...]}`. Empty `text` / `persona` → 422
  `{"error": "languages", "missing": ["en"]}`.
- Placeholders the server fills must stay: `shared` needs `{name}` and `{language}`; `modes.learn` needs
  `{explanations}`; `modes.intake` needs `{question}` and `{question_id}`. Submit (and approve/publish) of a version
  without one → 422 `{"error": "placeholders", "missing": ["{explanations}"]}` (in that order of the list above).
- `content.live_entries("persona")` = seed overlaid with published bodies (no cache). `chat.py` builds every system
  prompt from it (replace the module-level `PERSONAS` reads in `_persona`; the set of character ids still comes from
  the YAML). So an approved persona reaches the next chat turn; an unapproved one never does.
- Body keys other than the ones above → 422 (as T7-01).

## 4. Admin (part c): `web/admin.html` `<section id="personajes">` heading "Personajes" + `web/characters.js`
- Loads `GET /staff/characters`. One `<article>` per character with a heading = its name ("La Calavera", "El Oso", "Piñata"); every control
  below sits inside that article.
- Checkbox "Activo" (disabled for La Calavera, with the text "La Calavera no se puede desactivar."). One checkbox per
  unit, labeled: will "El testamento", trust "El fideicomiso", ahcd "La directiva de salud", poa "El poder notarial",
  final "Cuide sus documentos", bonus "Lecciones extra", games "Juegos", sensitive "Temas difíciles", intake "Tus datos".
  Button "Guardar" → `PATCH /characters/{id}` with `{"enabled", "units"}`.
- Voice preview: input "Frase para escuchar" (default "Hola, soy <name>. Soy un programa de inteligencia artificial, no
  soy el abogado."), select "Idioma" (es → `lang = "es-MX"`, en → `"en-US"`), button "Escuchar voz" →
  `speechSynthesis.cancel()` then `speechSynthesis.speak(new SpeechSynthesisUtterance(line))` with that `lang`.
  **No request to the server** for the preview.
- In "Contenido", the "Tipo" select gains `persona` "Personajes (instrucciones)". Persona fields are labeled `text`,
  `persona`, `name (es)`, `name (en)`; approve/publish buttons follow T7-01 (attorney only for legal entries).
Text nodes only.
