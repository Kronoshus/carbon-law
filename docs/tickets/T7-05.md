## Goal
The firm sets, in one place, its office hours, holidays, data retention, the switches for voice recording, AI chat and
the extension, and `lessons_per_day`. The server enforces each one. Spec 11 "Firma"; brief section 3 "Firm controls";
decision PRs #52 (Q-D2 retention), #51 (Q-P5 one lesson a day).

## Reuse, do not duplicate
- Office hours and holidays **already exist** (T6-07): `PUT /staff/availability`, `PUT /staff/holidays` in
  `booking.py`, stored in `settings` keys `availability` and `holidays`. The timeline (`timeline.py`) and booking read
  the same `holidays` key: it stays the one holiday list. Keep both routes; only add one audit row to each
  (`log_audit(email, "firm_settings", "settings", "availability"|"holidays", <json>)`).
- `lessons_per_day` **already exists** as the `settings` key read by `learn._lessons_per_day()` (migration 0005,
  default 1). Only add a way to set it.
- No new settings table: every value is a row in `settings` (`key`, `value_json`, `updated_by`, `updated_at`).

SWITCHES = ("voice_recording", "ai_chat", "extension")

|---|---|---|---|---|
| `GET /staff/firm-settings` | paralegal, attorney, admin | — | `firm.get()` | 401 / 403 |
| `PUT /staff/firm-settings` | **attorney, admin** | any of `{"switches": {name: bool}` (partial), `"retention": {"unpaid_personal_data_days": int ≥ 30}`, `"lessons_per_day": int 1–4}` | `firm.get()` | 401; 403 paralegal/client; 422 any other key (e.g. `holidays`, `availability`: they have their own routes), unknown switch or retention key, bad value. `log_audit(email, "firm_settings", "settings", <key>, <new value as json>)`.

## Enforcement
1. **AI chat off** → `POST /chat` answers **503 `{"error": "ai_chat_off"}`** right after the caller is identified
   (401/403 first), before gates and before any model call, for both modes. Lessons, attempts, completion, `/datos`
   answers, payments: unchanged. Drafting by the worker is the firm's work, not chat: not affected.
2. **Extension off** → every request whose `Origin` header starts with `chrome-extension://` (or equals
   `APRENDE_EXTENSION_ORIGIN`) gets **503 `{"error": "extension_off"}`**, except `/health`. The response must still
   carry the CORS headers (`access-control-allow-origin` = that origin when it is allowed), or the extension cannot read
   it: the check runs **inside** `CORSMiddleware`. Requests without that Origin (the web app) are untouched.
3. **Voice recording off**: there is no audio route yet (F-003: browser voice only, no recording). `firm.switch(
   "voice_recording")` is exposed in `/settings/public`; the voice ticket must check it. Nothing else to enforce now.
4. **lessons_per_day**: `learn.py` already reads the row on every call; the new PUT makes it settable. No cache.
5. **Retention**: new `backend/aprende/retention.py`
   ```python
   def sweep(now: datetime) -> dict     # {"journeys": n} — journeys whose personal data was deleted
   def schedule(at: datetime) -> None   # jobs.enqueue("retention_sweep", f"retention_sweep:{at:%Y-%m-%d}", run_after=at)
   jobs.register("retention_sweep", _job)   # _job(job): sweep(now), then schedule() for tomorrow 03:00 America/Los_Angeles
   ```
   A journey is swept when it has **no `paid` fact** and its last activity — the latest of `journeys.started_at`,
   `journey_events.created_at`, `datos_answers.updated_at`, `item_attempts.created_at` — is more than
   `retention.unpaid_personal_data_days` days before `now`. Sweeping deletes that journey's `datos_answers`,
   `datos_audit` and `attorney_questions` rows, and writes one `log_audit("retention", "retention_sweep", "journey",
   journey_id, "<counts>")` (counts only, never text). The account, journey, events, lesson progress and conflict
   records stay. The setting is read at each sweep (a change takes effect at the next sweep, not before).
   `worker.run_forever` schedules the first sweep next to `timeline.schedule`.

## Client app (part b), `aprende/`
- `src/core/api.ts` `apiFetch`: a 503 whose JSON `error` is `extension_off` sets a signal; `App` then renders only the
  `NoDisponible` screen (heading `unavailable.title`, text `unavailable.body`).
- The extension side panel and popup call `GET /settings/public` at start (so a signed-out user sees it too).
- `Datos.tsx`: a 503 with `error: "ai_chat_off"` shows `chat.off` and the existing "Volver al mapa" button (no error
  styling, no retry loop).
- i18n (es / en):
  - `unavailable.title`: "No disponible" / "Not available"
  - `unavailable.body`: "Aprende y Planea no está disponible en la extensión por ahora. Puede usarla en
    carbon.bailment.tech/aprende/." / "Aprende y Planea is not available in the extension right now. You can use it at
    carbon.bailment.tech/aprende/."
  - `chat.off`: "La charla con los personajes no está disponible por ahora. Puede seguir con sus lecciones." /
    "Chatting with the characters is not available right now. You can keep going with your lessons."

## Admin (part c): `web/admin.html` section `<section id="firma">` heading "Firma" + `web/firm.js`
Loads `GET /staff/firm-settings`. Checkboxes labeled "Grabación de voz", "Charla con IA", "Extensión de Chrome"; number
inputs "Lecciones por día" and "Borrar datos de quien no pagó después de (días)"; button "Guardar ajustes" sends only the
changed keys to `PUT /staff/firm-settings`. Holidays: a date input "Día feriado" + "Agregar feriado" sends the whole list
to the existing `PUT /staff/holidays`. Office hours: one row per weekday with "Desde"/"Hasta" time inputs + "Guardar
horario" sends the existing `PUT /staff/availability` body. A paralegal sees the values read-only (inputs disabled) with
the text "Solo el abogado o un administrador puede cambiar estos ajustes." (holidays/hours stay editable, as today).
Text nodes only.
