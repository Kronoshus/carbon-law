# T8-05 · Performance on a mid-range phone — builder brief

Written by the Opus test writer (p8-tests) on 2026-11-20. Branch `feat/t8-05-performance` (from origin/main ae1d3c4;
backlog: after T8-03, so merge `origin/main` once T8-03 is in and re-run). The acceptance tests are on the branch; make
them pass without editing them. Size M.

## Goal
Spec 13 budget on a Moto G Power–class phone: Lighthouse mobile performance ≥ 90 on the map and on the lesson; initial JS
≤ 170 KB gzip before the character engine; three.js and the character GLB only after the first paint and only on screens
with a character stage; INP < 200 ms on the lesson player. Guides: `performance` (code splitting, fonts, images, INP:
yield in long handlers), `interaction-paint-timing` (web-vitals).

## Where things stand (measured by the test writer on main ae1d3c4)
- Initial JS today: web entry `index-*.js` ≈ 35 KB gzip; three.js (172 KB gzip) and GLTFLoader (14 KB) are already
  dynamic chunks loaded by `CharacterStage`, so the budget and "after first paint" tests **pass now**: they are guards
  that keep it so. The side panel entry is ≈ 16 KB + a 19 KB shared chunk.
- The map loads no three.js and no GLB (passes now: a guard).
- INP on the lesson player with the CPU slowed 4×: 136 ms worst (two interactions measured, 16 and 136 ms; load average 4),
  with web-vitals 5 from a scratch folder. So this test fails now only because `web-vitals` is not a devDependency.
- Lighthouse: not run yet; that is your first job (below).
- 28 font files (Work Sans 400/600/700, League Spartan 700/800, each with latin, latin-ext, vietnamese, woff and woff2)
  are bundled by `@fontsource/*` imports. Import only the latin subsets you need (`@fontsource/work-sans/latin-400.css`
  etc.) and preload the one or two used above the fold, if Lighthouse asks for it.

## What to build
1. **`aprende/scripts/lighthouse.mjs`** (devDependencies `lighthouse` and `puppeteer-core`; Chrome from `PW_CHROMIUM`
   or `CHROME_PATH`). Against the **production build** served by `vite preview` (its proxy is the dev proxy, so the API
   works; start the backend with `scripts/start-e2e-backend.sh`):
   - sign up a fictional client (Ana Torres) through `/auth/signup`, post `ai_disclosed`, `consent yes`,
     `names_submitted ["Ana Torres"]`;
   - for `#/aprender` and `#/leccion/will`: a Lighthouse navigation with the default mobile config (simulated
     throttling = Moto G Power), `onlyCategories: ['performance']`, the token set in `localStorage` before load
     (`page.evaluateOnNewDocument`);
   - print `map: <score>` and `lesson: <score>`, write the JSON reports to `aprende/lighthouse/` (git-ignored), and exit 1
     if either score is below 90.
   - Usage: `node scripts/lighthouse.mjs --url http://127.0.0.1:<port>/`.
   If it runs headless on this machine, put both scores in your report. If it cannot, say exactly why (error text).
2. **CI job `lighthouse`** in `.github/workflows/ci.yml` (Ubuntu): set up Python and Node, install, `npx playwright install
   chromium`, `npm run build:web`, start the e2e backend and `npx vite preview --port 4173 --strictPort` in the background,
   wait for both, run the script with `PW_CHROMIUM` set to Playwright's Chromium, and upload `aprende/lighthouse/` as an
   artifact. The job fails when the script fails.
3. Fix what Lighthouse and the INP test show, in this order: fonts (subsets, `font-display: swap` is in fontsource),
   images (`width`/`height` on every `<img>`, the character PNG/JPEG still sized for the stage, `loading="lazy"` below the
   fold), the stage (mount `CharacterStage`'s engine after first paint with `requestIdleCallback` or after the first
   frame; keep the still image until the GLB is ready; pause the render loop when the canvas is off screen or the tab is
   hidden), and long tasks in the lesson's click handlers (split with `scheduler.yield()` where supported, else
   `setTimeout(0)`). Do not drop the character, the voice or any content to reach a score.
4. `web-vitals` as a devDependency (the INP test loads `node_modules/web-vitals/dist/web-vitals.iife.js`). Install it in
   your worktree with your own `npm ci` (replace the `node_modules` symlink); never install into the lead's clone.
