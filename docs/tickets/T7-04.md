# T7-04 · Clients admin — builder brief

Written by the Opus test writer (t7-tests) on 2026-11-19. Branch `feat/t7-04-clients-admin`. The acceptance tests are
on the branch; make them pass without editing them.

## Goal
Spec 11 "Clientes": one staff list with, per client, the journey day, late steps, conflict state, datos completeness,
payment, drafts waiting, appointments and questions for the attorney. The attorney answers a question in a reply box;
the client reads the answer in the Preguntas tab. A client gets 403 on every staff route. No page a paralegal might
show a client carries conflict match names (only the neutral state `pending | clear | hold`, spec 5 / T5-03).

## Staff guard (part a) — one check at the boundary
Add one middleware (in `app.py`, next to the existing ones) for paths starting with `/staff/` or `/conflicts`, and
`/chat/attorney-questions`: no or unknown token → 401 `{"detail": "not authenticated"}`; role `client` → 403
`{"detail": "insufficient role"}`. It runs **before** body validation, so a client never gets 422 from a staff route.
Use `backend_app.get_user_from_token`. Handlers keep their own finer role checks (attorney-only etc.).

## Routes
| Method + path | Roles | 200 response | Errors |
|---|---|---|---|
| `GET /staff/journeys` (exists, T6-09: **keep every current key and the sort**) | staff | rows gain: `"conflict": "pending"\|"clear"\|"hold"`, `"datos": {"done": int, "total": int, "complete": bool}`, `"payment": {"paid": bool, "paid_cents": int, "refunded_cents": int}`, `"drafts_waiting": int`, `"appointments": [{"kind", "start_utc"}]`, `"questions": {"open": int, "answered": int}` | 401/403 |
| `GET /staff/journeys/{jid}` (new) | staff | the same row + `"timeline": [...]` (`timeline.for_journey`) + `"questions": [{"id", "question", "lesson_id", "character", "created_at", "answer", "answered_by", "answered_at"}]` (oldest first) | 404 |
| `POST /staff/attorney-questions/{qid}/answer` (new) | **attorney only** | body `{"answer": str}` (1–4000 chars after strip) → `{"id", "answer", "answered_by", "answered_at"}`; a second answer replaces the first | 403; 404; 422 |
| `GET /journey/questions` (new, client) | the client (own journey only) | `{"questions": [{"id", "question", "created_at", "answer": str\|null, "answered_at": str\|null}]}` newest first; never `answered_by` (a staff email) | 401; 403 staff |

Definitions (reuse, do not copy):
- `conflict` = the journey's own `conflict` (`journey.conflict_status`), the value the client sees.
- `datos` from `datos.get_datos(j)`: `total` = applicable questions, `done` = answered or skipped, `complete` = none open.
- `payment`: `paid` = the `paid` fact; `paid_cents` = sum of `payments.amount_cents`; `refunded_cents` = sum of `refunds`.
- `drafts_waiting` = `len(review._current_drafts(jid))` (the attorney queue's own rule).
- `appointments` = `bookings` rows with `status = 'active'`, sorted by `start_utc`.
- Answering writes `log_audit(email, "answer", "attorney_question", qid, "")` — **no question or answer text in the audit
  detail**, no client name. No staff phone alert.
- **Never** read `conflict_checks.names_json/matches_json` or `/conflicts/queue` for any of these routes or the screen.

## Client app (part b): `aprende/src/ui/screens/Preguntas.tsx`, route `#/preguntas` in `App.tsx` (replaces the placeholder)
Loads `GET /journey/questions`. Heading `preguntas.title`. Each question: the client's words, then either the label
`preguntas.answer` with the answer, or `preguntas.waiting`. Empty list: `preguntas.none`. Text through Preact children
only (no `dangerouslySetInnerHTML`). i18n (es / en):
- `preguntas.title`: "Preguntas para el abogado" / "Questions for the attorney"
- `preguntas.answer`: "Respuesta del abogado Raval:" / "Attorney Raval's answer:"
- `preguntas.waiting`: "El abogado Raval todavía no ha respondido." / "Attorney Raval has not answered yet."
- `preguntas.none`: "Todavía no tiene preguntas para el abogado. Si le pregunta algo sobre su caso a un personaje, la
  pregunta aparece aquí." / "You have no questions for the attorney yet. If you ask a character something about your own
  case, the question appears here."

## Admin (part c): `web/admin.html` `<section id="clientes">` heading "Clientes" + `web/clients.js`
Table from `GET /staff/journeys`, headers: Cliente, Día, Atrasos, Conflicto, Datos, Pago, Borradores, Citas, Preguntas.
Conflict labels: `pending` "Pendiente", `clear` "Sin conflicto", `hold` "En revisión". Datos "`done` de `total`". Pago
"Pagado"/"Sin pagar". The client name is a button; it opens the detail (`GET /staff/journeys/{jid}`): each question with
its answer, and for the attorney (role from `/auth/me`) a textarea labeled "Respuesta del abogado" + button
"Enviar respuesta" (POST answer). Others see "Solo el abogado responde las preguntas." Text nodes only.
