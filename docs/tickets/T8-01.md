## Goal
The Chrome side panel shows today's lesson without scrolling on a small panel, and the toolbar popup shows the client's
real streak and today's step. Design doc section 9 ("Chrome side panel", "Chrome popup"), spec 4.1, backlog T8-01.

- `aprende/src/targets/extension/Popup.tsx`, `popup.css`, `popup.html`
- `aprende/src/ui/screens/map.css` (and `Aprender.tsx` only if CSS alone cannot do it)
- `aprende/i18n/{es,en}.json`, then `npm run i18n:types && npm run i18n:check`

## Popup (exact behaviour)
1. **No token** (`getToken()` is null): show the face, the text `popup.signedOut` and the "Abrir" button. Do not show
   a day, a streak or a step, and do not call `/journey`, `/progress` or `/learn/map`.
2. **Signed in**: `GET /settings/public` (as today), then `GET /journey`, `GET /progress`, `GET /learn/map`.
   - Streak: `progress.streak.count` → `popup.streak` (replaces the fixed 0). If `/progress` fails, show 0.
   - Day: `journey.day` → `popup.today` (as today).
   - Today's step: if `may_disclose`, `may_consent` and `may_name` are all true and `/learn/map` has an `available`
     lesson in units `will`, `trust`, `ahcd`, `poa` (lowest `day` first) or `final`, show that lesson's
     `title[lang]`. Otherwise keep today's rule: the first false gate in `GATE_ORDER` → its `popup.gate.*` label, or
     `popup.complete`.
3. The page has one `<h1>`: the title `top.title` ("Aprende y Planea"), visible or visually hidden. Zero axe violations.
4. No character stage: no `CharacterStage`, no canvas, no import that pulls in `three` (directly or through
   `src/ui/App`). The popup's static imports are checked in the build output.
5. "Abrir" keeps calling `chrome.sidePanel.open({ windowId })` exactly as now (the T2-12 test spies on it).

i18n (es / en):
- `popup.signedOut`: "Inicie sesión en el panel para ver su día." / "Sign in in the panel to see your day."

## Side panel at 320–360 × 640
Today's node (the `.node.current` card with the "Empezar" link) must be fully visible above the fixed bottom tabs with
no scrolling, at 360 × 640 and at 320 × 640, with no sideways scroll. Design doc section 9: "the host bubble collapses to
one line when height < 700 px so today's lesson stays above the fold". Do it in CSS with a height media query
(`@media (max-height: 700px)` or a range query), for example: a one-line host bubble (`text-overflow: ellipsis` on the
bubble, its full text stays in the DOM), a smaller day chip row, and the price card placed after today's node through
CSS `order` on the `.map` grid. The price card stays on the map with all its text (the `map.spec.ts` test reads it).
The same rules apply to the web app on a short phone screen; that is fine.

## Microphone (backlog test replaced)
The backlog asks "the microphone works from the side panel via the offscreen document after a click". F-003 (firm
answer, 2026-11-17): no server voice; the browser's `speechSynthesis` and typed answers. No screen uses the microphone,
so **do not build microphone capture**. The test instead proves that no extension page calls `getUserMedia`. The unused
`offscreen` permission and file are T8-02's to remove; leave them here.
