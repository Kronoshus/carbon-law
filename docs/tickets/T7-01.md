## Goal
Staff edit lesson items, the "Tus datos" questions and the day-9 summaries in the admin without a developer.
A paralegal edits and submits; only the attorney approves a legal entry, and his approval publishes it. The approval
records who, when and which version. Editing a published entry makes a new draft version; the old version stays live
until the new one is approved. Both languages are required to submit, approve or publish. Every change is audited.
(Spec 10 "Attorney approval of legal wording", spec 11 "Contenido", decision PR #50 Q-L2: item by item, the app records
who approved which version.)

## Entries (what can be edited)
| kind | `entry_id` | editable `body` | legal? | live copy today |
|---|---|---|---|---|
| `item` | the lesson item id, e.g. `will.1.1` | `{"es": {...}, "en": {...}, "answer"?: any, "source"?: str}` — same field names as the YAML item (FORMAT.md) | `content_items.legal` | the `content_items` row (`learn.py` serves `state='published'`) |
| `datos` | `datos:<question id>`, e.g. `datos:legados` | `{"es": str, "en": str}` | always | `aprende/content/datos.yaml` (seed) |
| `summary` | `summary:<doc>.<article>`, e.g. `summary:will.3` | `{"es": str, "en": str}` | always | `aprende/content/summaries.yaml` (seed) |

`kind`, `legal`, `sensitive`, `character`, `asked_after`, `docs` are **not** editable here (a body with any other key
→ 422). Personas are **not** in this ticket: T7-03 adds `kind = persona` to the same functions.
New ids (new items/questions) still come from the YAML import; this ticket edits existing entries only.

## Migration `backend/migrations/0016_content_versions.sql`
```sql
CREATE TABLE IF NOT EXISTS content_versions (
  entry_id TEXT NOT NULL,
  version INTEGER NOT NULL,
  kind TEXT NOT NULL,
  body_json TEXT NOT NULL,
  state TEXT NOT NULL,
  created_by TEXT NOT NULL,
  created_at TEXT NOT NULL,
  submitted_by TEXT,
  submitted_at TEXT,
  published_by TEXT,
  published_at TEXT,
  PRIMARY KEY (entry_id, version)
)
```
`state`: `draft | review | published | superseded`. **Approvals stay in the existing `content_approvals`**
(`item_id` = `entry_id`, `version`, `attorney` = his email, `approved_at` ISO UTC) for every kind: one approval record,
no second table, no approval columns on `content_versions`.

## Version rules
- New version number = 1 + the highest of: any `content_versions.version` for the entry, `content_items.version` (items).
  Seed-only datos/summary entries have live version `0`.
- `PUT .../draft`: if the newest version is `draft`, update it in place; otherwise create a new `draft` version.
  A draft may lack a language.
- Publishing version N (by approval or by publish): N → `published` (`published_by/at` set), the previous published
  version → `superseded`. For `item`, the same transaction writes N's body into the `content_items` row
  (`payload_json_es/en`, `answer`, `source_id`, `version = N`, `state = 'published'`), so `learn.py` stays unchanged.
- The first time an item is touched by any function below, its current `content_items` row is copied into
  `content_versions` as its own version (`created_by = 'import'`; state `published` if it is live, else `review`).
  So an item imported by the YAML CLI is approved from the admin as its `content_items.version` (the seed path for
  the 130 lesson items), and every version's text is kept.
- A version in `review` is frozen: `PUT .../draft` on it marks it `superseded` and creates a new draft. So the attorney
  always approves exactly the text he read.
- Approve accepts only the pending version in state `review`. Publish (non-legal only) accepts `draft` or `review`.
- Languages: `body.es` and `body.en` must both be present and every string in them non-empty after `strip()` (lists and
  pairs: every element).
- List `pending` = the newest version in `draft` or `review`; detail textareas show the pending body, else the live body.

## Functions in `backend/aprende/content.py` (existing functions unchanged)
```python
def entries(kind: str) -> list[dict]          # list rows (see GET /staff/content); KeyError for an unknown kind

                                                                # published version; reads the DB on every call (no cache)
```

`docs`, article numbers) still comes from the YAML.

## Routes: new `backend/aprende/routes_content.py`, mounted in `app.py` (prefix `/staff` is already in `APRENDE_PREFIXES`)
Roles: **staff** = paralegal, attorney, admin. No token → 401; a client → 403 on every route below.

| Method + path | Roles | Body | 200 response | Errors |
|---|---|---|---|---|
| `GET /staff/content?kind=item\|datos\|summary` | staff | — | `{"entries": [{"entry_id", "kind", "legal": bool, "live_version": int\|null, "pending": {"version", "state"}\|null}]}` (items also `"lesson_id"`) | 422 unknown kind |
| `GET /staff/content/{entry_id}` | staff | — | `{"entry_id", "kind", "legal", "live": {"version", "body"}\|null, "versions": [{"version", "state", "body", "created_by", "created_at", "submitted_by", "submitted_at", "approved_by", "approved_at", "published_by", "published_at"}]}` newest first; `approved_*` from `content_approvals` | 404 |
| `PUT /staff/content/{entry_id}/draft` | staff | `{"body": {...}}` | `{"entry_id", "version", "state": "draft"}` | 404; 422 bad shape / extra key |
| `POST /staff/content/{entry_id}/submit` | staff | — | `{"entry_id", "version", "state": "review"}` | 404; 409 no draft; 422 `{"error": "languages", "missing": [...]}` |
| `POST /staff/content/{entry_id}/approve` | **attorney only** | `{"version": int}` | `{"entry_id", "version", "state": "published", "approved_by", "approved_at"}` | 403 not attorney; 404; 409 version is not the pending `review` version; 422 languages |
| `POST /staff/content/{entry_id}/publish` | staff | `{"version": int}` | `{"entry_id", "version", "state": "published"}` | **403 `{"error": "attorney_approval_required"}` for any legal entry, whoever asks**; 404; 409; 422 languages |
| `GET /staff/content/{entry_id}/preview?version=N&lang=es` | staff | — | item: `{"character": item.character or the lesson's, "item": <learn._serve shape: no answer, no explain>, "explain": str\|null}`; datos/summary: `{"character": null, "text": str}` (`version=0` = the YAML seed) | 404 |

Error bodies with `error` are returned as JSON content (like the journey's 409 gate), not under `detail`.

## Audit
Every successful draft / submit / approve / publish writes one `backend_app.log_audit(actor_email, action, "content",
entry_id, f"version={n}")`, action `content_draft`, `content_submit`, `content_approve`, `content_publish`
(an approval also publishes and writes only `content_approve`).

## Admin UI (part c): `web/admin.html` section + new `web/content.js` (plain JS, text nodes only, Spanish labels)
- `<section id="contenido">`, heading "Contenido"; opened at `admin.html#contenido`; calls the API above.
- Select labeled "Tipo" (`item` "Lecciones", `datos` "Tus datos", `summary` "Resúmenes"); one button per entry whose
  accessible name starts with the `entry_id`.
- Detail: "Publicada: versión N" and "Pendiente: versión N (borrador|en revisión)". One textarea per string, labeled
  `<field> (es)` / `<field> (en)` (list elements `<field> <i> (es)`, 1-based; match pairs `pairs <i>a (es)`/`<i>b`);
  datos/summary: `texto (es)` / `texto (en)`.
- Buttons: "Guardar borrador" (PUT draft with every field of the body, never `legal`), "Enviar a revisión" (submit),
  "Vista previa" (preview of the pending version, else the live one, rendered as text into `.content-preview`).
  Legal entry: "Aprobar versión N" only when the signed-in user is the attorney (role from `/auth/me`); everyone else sees
  the text "Solo el abogado puede aprobar y publicar este contenido." and no approve/publish button.
  Non-legal entry: "Publicar versión N" for any staff.
- A 422 `languages` answer shows "Faltan los dos idiomas para publicar: <es/en>." in the section's `role="status"`.
